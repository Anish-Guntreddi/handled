**Findings**

- **High** [services/approvals.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/approvals.py:37), [api/filings.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/api/filings.py:184): the approval state machine is not enforced. An editor can `POST /approvals` with `target=package, decision=approved` on any filing and jump straight to `ready`; `target=recommendation, decision=approved` also moves to `approved` even if no `Recommendation` row exists. I did not see an automatic workflow transition to `approved`/`ready`, but this endpoint lets callers skip the intended gates.

- **High** [services/company_brain.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/company_brain.py:150), [models/filings.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/models/filings.py:99), [services/compliance.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/compliance.py:55): `company_brain` deletes all org-wide `inferred` `EvidenceItem`s. Because `EvidenceMatch.evidence_item_id` is `ON DELETE SET NULL`, existing `matched`/`partial` rows can be left with no resolvable evidence item, and the compliance matrix will still surface the old status with `evidence_item_id=None`. That breaks CON-2 after the fact.

- **Medium** [ingestion/service.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/ingestion/service.py:66), [services/gaps.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/gaps.py:83): deduped documents are not citable for gap resolution. The dedupe path returns a parsed `Document` without creating a `Source`; later `resolve_gap` assumes every document has one and creates `EvidenceItem(source_id=None)`, which will fail on flush.

- **Medium** [services/gaps.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/gaps.py:64), [services/evidence.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/evidence.py:126): rerunning `/match-evidence` can erase human gap resolutions. `resolve_gap(value=...)` stores only the raw value as evidence; `map_evidence` then deletes all matches and tries to rediscover `user_provided` evidence by lexical overlap. Values like UEI/CAGE numbers often have zero overlap with the requirement text, so a later rematch turns `user_provided` back into `missing`.

- **Medium** [agents/matching.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/agents/matching.py:79), [services/evidence.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/evidence.py:146): match status is not enum-validated. The LLM output model accepts any string, and `map_evidence` persists it. In non-mock mode, an unexpected status like `user_provided` or arbitrary text can be stored against inferred evidence and skew `gap_rows`, `match_summary`, and recommendation inputs.

- **Low** [services/evidence.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/evidence.py:92), [services/evidence.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/evidence.py:123): the match workflow is easy to self-DoS. It loads the entire org evidence vault, sorts it for every requirement, recomputes overlap repeatedly, and does a per-chunk `Source` lookup in acquisition. Large org corpora can make one match run disproportionately expensive.

- **Low** [api/filings.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/api/filings.py:216), [services/recommendation.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/recommendation.py:28), [services/compliance.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/compliance.py:20), [services/approvals.py](/Users/anishguntreddi/Documents/hackathon/apps/api/captureos/services/approvals.py:39): I did not find a direct happy-path tenant breakout in the M4 APIs, but several secondary lookups omit redundant `org_id` filters and trust the already-scoped `filing_id`. If a mismatched cross-tenant row ever exists, these paths can read or mutate another org’s `Opportunity`/`Recommendation`/`Approval`/`EvidenceItem` data.

**Notes**

No SQL injection or regex ReDoS issue stood out in `agents/matching.py` / `ingestion/retrieval.py`. `_significant_words` uses a fixed linear regex, and `retrieve_relevant_chunks` uses SQLAlchemy/pgvector parameterization with `DocumentChunk.org_id == org_id`; `cosine_distance` usage itself looks correct.
